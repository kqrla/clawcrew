# directive

what this thing is for, and what it will not do. not a spec: a spec says how a feature works, a
directive says what survives a change of plan. anything here that gets contradicted by a spec is a
bug in the spec.

## why this folder exists at all

a self-directed org has nobody to ask mid-flight. every decision it faces for a month has to be
answerable from what it already believes, so the beliefs have to be written down, short, and
checkable. a directive that takes an hour to read is a directive nobody applies at 3am.

## the four sentences

1. **the work is a business, not a demo.** a project ships something a stranger pays for, or it is
   stopped. nothing here is judged by how sophisticated it looks.
2. **evidence or a gap.** a claim about the world is either bound to something another party can
   check, or it is recorded as a gap. there is no third state, and "high confidence" is not a
   substitute for a reference.
3. **the future is a plan, never a fact.** roadmap language never counts as capability. this is
   `way.md` from the nine w's and it is the rule most self-directed systems die by breaking.
4. **the org may not certify itself.** no tier owns the number that decides whether it is working.

## pages

- [positioning](positioning.md): who it is for, what it is, why it is worth doing, in the terms of
  the nine w's, with the evidence rule applied to this project rather than to a product.
- [refusals](refusals.md): the standing no's. things this org has decided not to do, and the
  condition that would make a yes defensible.
- [invariants](invariants.md): the rules that cannot be traded for speed, each named with the code
  that enforces it. an invariant with no enforcement is a wish.
